## 1. Pergunta científica

> O comportamento atual da ADArena é estável quando o mesmo experimento é repetido com diferentes seeds?

A execução de referência mostrou um padrão claro:

```text
Attacker encontra variantes com evasão
        ↓
Defender é exposto às variantes
        ↓
evasão diminui após adaptação
```

Antes de modificar Attacker ou Defender, é necessário verificar se esse comportamento se mantém quando a inicialização muda.

---

## 2. Hipótese

> Mantendo dataset, arquitetura e hiperparâmetros constantes, seeds diferentes devem produzir variação quantitativa nas métricas, mas preservar o comportamento qualitativo de adaptação do Defender.

Não é esperado que as execuções produzam números idênticos.

O comportamento qualitativo esperado é:

```text
seed diferente
      ↓
Attacker encontra capacidade de evasão
      ↓
Defender adapta
      ↓
evasão pós-adaptação < evasão pré-adaptação
```

Se uma seed produzir comportamento muito diferente, essa variabilidade deverá ser investigada antes de alterar os modelos.

---

## 3. Objetivo

O E0 serve como baseline da linha v2.7.

Ele deve:

- produzir as primeiras métricas organizadas desta fase;
- estimar a variabilidade entre execuções;
- verificar a estabilidade do ciclo adversarial;
- estabelecer valores de referência;
- identificar métricas ausentes ou inadequadas;
- revelar problemas evidentes do modelo atual antes de modificá-lo.

O E0 **não tenta provar generalização para ataques não vistos**.

## 7. Como as métricas serão coletadas

Para cada seed:

1. preparar uma configuração equivalente à baseline;
2. alterar apenas a seed;
3. executar `TRAIN`;
4. preservar o run completo;
5. registrar o `run_id`;
6. coletar métricas finais do Defender;
7. coletar métricas adversariais por rodada;
8. preservar matriz de checkpoints e gráficos;
9. comparar as execuções somente depois que todas terminarem.

Os valores usados na análise devem vir preferencialmente dos artefatos persistidos, evitando copiar manualmente do terminal quando o mesmo dado existir em JSON ou CSV.

```text

```

Se alguma métrica ainda não for produzida pelo pipeline atual, isso será registrado como limitação da coleta.

Uma métrica ausente pode ser calculada posteriormente a partir dos dados persistidos, se houver informação suficiente. Isso não exige mudança na arquitetura.

### 9.2 Robustez adversarial

Para cada rodada:

```text
evasão pré-adaptação
evasão pós-adaptação
```

Será derivado:

```text
ganho_adaptacao_r
=
evasao_pre_r - evasao_pos_r
```

e, quando útil:

```text
robust_detection_rate
=
1 - evasao
```

### 9.3 Estabilidade

Depois das três execuções:

```text
média
desvio padrão
mínimo
máximo
```

para as métricas principais.

## 14. Critérios de análise

A análise não exige valores idênticos.

Ela deve observar principalmente:

### 14.1 Existência de evasão

O Attacker consegue reduzir a detecção antes da adaptação?

### 14.2 Efeito da adaptação

A evasão pós-adaptação é consistentemente menor?

### 14.3 Variância

A intensidade do efeito muda muito entre seeds?

### 14.4 Desempenho convencional

O Defender mantém bom desempenho no conjunto reservado após o ciclo?

### 14.5 Comportamentos anômalos

Alguma seed:

- não encontra evasão;
- mantém evasão alta após adaptação;
- degrada fortemente o desempenho convencional;
- possui uma ou mais rodadas muito diferentes das demais?

Esses casos podem indicar limitações importantes do modelo atual.

## 16. Análise

> Atualizar após a coleta das três execuções.

Perguntas orientadoras:

1. O padrão de adaptação apareceu em todas as seeds?
2. A magnitude da evasão pré-adaptação foi semelhante?
3. O Defender reduziu a evasão em todas as execuções?
4. Alguma seed foi claramente mais difícil?
5. O desempenho convencional permaneceu estável?
6. Qual é a variabilidade das métricas principais?
7. Algum comportamento justifica alterar Attacker ou Defender antes do próximo experimento?

---

## 17. Limitações

Limitações intencionais do E0:

- apenas três seeds na primeira coleta;
- um único dataset principal;
- mesma família de ataque;
- mesmo Attacker;
- mesmo Defender;
- ainda não mede generalização cross-seed;
- ainda não mede novelty sob definições mais fortes;
- não compara arquiteturas alternativas.

O experimento tenta isolar apenas a estabilidade da configuração atual.
